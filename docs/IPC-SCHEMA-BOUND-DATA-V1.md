# Candidate schema-bound DATA subprofile

Use existing v3 authenticated DATA payload with a domain-specific ASD1 prefix, stable codec byte, positive signed 32-bit schema version, bounded printable ASCII nominal ID, 32-byte trusted descriptor digest, and exact bounded body length. All fields are within the outer SHA-256 payload digest and HMAC. The recipient compares to a registration-pinned binding after MAC, transport epoch, destination incarnation and replay validation. The existing replay gate consumes authenticated sequence before schema validation; a schema refusal is terminal for that frame, not replay authorization. No fallback to legacy DATA. This is opt-in host framing, not negotiation, peer trust establishment, canonical descriptor hashing, mailbox publication or compiler guest evidence. Existing DATA framing unchanged. The body copy is bounded but not tenant-credit-accounted here; production admission must reserve the snapshot/copy budget before parsing. No guest-visible authority.
