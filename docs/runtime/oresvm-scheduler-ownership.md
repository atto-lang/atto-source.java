# OresVM scheduler ownership — current-main reconciliation

This port reconciles historical #617 with Java main de75927cba956ef81b363b47cb6767335ed2330d rather than restoring its older executor implementation. One VM admits one ActorRuntime and retains its CONTROL and physical STOP dispatch until actor/carrier retirement succeeds. Blocking actor teardown and all executor joins occur outside the VM admission monitor; a competing close is explicitly rejected instead of claiming physical completion. Context shutdown retains the current coordinated native-I/O/actor join, quarantine and stdio order and records successful actor retirement before VM teardown.

Current main already includes multi-membership quotas, publisher revalidation, watchdog fault isolation, native descriptor-only startup, demand-grown actor lanes and corresponding regression tests. Preserve those newer implementations and the extra raw join-capability negative test. Preserve main's bounded CPU-aware carrier budgets, prestarted CONTROL bootstrap and separate physical STOP/NIO domains: the historical fixed-five and zero-CONTROL-carrier proposals conflict with the current startup contract and require a separately reviewed policy decision (see ROOT/Mailman integration #574). No security-isolation claim follows from distinct carrier pools.

Adds current-main VM ownership regression and adapts the historical native cold-start/concurrent-first-submit tests to registered-carrier diagnostics. Exact-head JDK25 Maven, native lifecycle and compiled guest execution plus independent review remain required. No private source export.
