# P0(DB): Java/Graal runtime WAL file-owner source slice

**Status: independently locally compiled/tested host-side primitive. Not registered with the Oreslang compiler, not guest-callable, not an actor, not a database.** Tracks `oreslang-source.java#2358` and `oreslang-db#4` (stacked DB PR #11). The source is introduced under `dev.oreslang.runtime`, where a runtime-owned async disk provider will belong, rather than adding Java implementations of Oreslang database algorithms.

## Present, exactly

- `WalStorageFileOwner.openVerified`: package-private runtime-only *preopened* FileChannel adoption; refuses nonempty WAL. The trusted caller must verify a canonical confined tenant/shard storage root, actual isolate/actor identity and generation, and exclusive inode custody **before** calling it. This method is **not** a permission or a secure openat2/openat grant and must not be exposed to guest or reflection/Java interop.
- `appendAndSync`: validates whole ODB1 v1 frames, tenant, generation, monotonic sequence, and duplicate in-epoch operation IDs; copies guest-sourced bytes before queuing; limits outstanding operations to 32, WAL accepted bytes to 1 MiB, operation history to 4,096. A single bounded physical disk executor uses positional `FileChannel.write`, verifies size against prior synced offset and performs real `FileChannel.force(true)`; a distinct bounded completion executor delivers an opaque host-only `SyncReceipt` with defensive SHA-256.
- `revokeAndCloseAsync`: marks authority revoked immediately, quiesces physical work and completion handoffs off carriers, then closes the file descriptor. A timeout refuses FD closure. The async caller must retain this owner's storage lease on failure. Post-dispatch failures and revocations are `UnknownOutcome`, never definitely cancelled or retried; the owner quarantines uncertain physical results. No public `Committed` API exists.
- `WalStorageFileOwnerTest`: standalone host JDK21 test with 20 assertions, including scope/activation forgery, tenant rejection, invalid frames, independent physical write/reopen, duplicate/sequence rejection, byte-copy, digest-copy, asynchronous closure, read-only physical write failure and quarantine. This is **host test evidence** only.
- `scripts/verify-wal-storage-file-owner.sh`: independently provided exact source commit/tree and Java/Javac binary hashes required; fail closed on dirty checkout, missing toolchain, or oracle mismatch. A source-free GitHub runner canary still has to execute nonzero actual steps before CI success may be counted.
